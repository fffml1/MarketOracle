# 上车前辩论与动态轮数

具体开发步骤与验收用例见[实时多空辩论与短线评估实施方案](./02-实时多空辩论与短线评估实施方案.md)。

**状态：本轮产品方案已确认。** 用户可以先听多空理由，再补个人风险上限。短线评估和完整研报都逐段展示公开发言。第一版均从一轮开始，最多试行三轮。续辩判断方式和时间预算通过案例验证。

## 用户希望解决什么问题

> “帮我看看这只票现在能不能上车。我打算做个短线波段，止损最多扛 3%。”

用户希望有人替自己认真质疑这笔交易。助手沿用当前会话的股票和基准日，提取持有意图、可承受的价格跌幅，以及用户给出的拟入场价或利好消息。收到足够信息后进入多空辩论。小白模式先展示多头最强理由、空头最强反驳、风险条件下的结论，以及什么情况值得重新评估。用户可以继续问“多头怎么回应这条质疑？”并查看原话和证据。

第一版候选范围是单股、盘后、短线入场评估。使用用户拟入场价时标明“用户假设”；若采用行情参考价，展示最近有效交易日、收盘价和来源。日线只能支撑截至该收盘时点的判断。“3%”暂按相对入场价的价格跌幅解释；若用户说的是账户损失或仓位风险，需要先明确口径。

## 让风险条件真正参与判断

缺少个人风险上限时，先展示双方理由、依据和失效条件，标明个人承受能力待确认。用户只补风险上限且其余条件相同时，复用实录和证据完成比较。

程序计算止损参考价：拟入场价 ×（1 − 最大可承受跌幅）。多头需说明哪项事实或哪个价位会推翻交易理由，并给出依据；空头可以质疑该依据。若理由失效取决于消息真伪等非价格条件，就单独保留这一条件，避免虚构一个失效价。

假设拟入场价是 100 元，双方接受的价格失效位是 96 元。3% 对应 97 元，用户会先触及自己的风险线；改为 5% 后，对应 95 元，96 元已落入预算范围。后者只表明这项价格约束满足，消息可信度和入场条件仍需判断。止损参考价用于比较计划，实际成交可能受跳空和滑点影响。

裁决候选项为“符合所列条件”“等待确认”“超出风险范围”“证据不足”。每次给出决定性依据、仍待确认的事项、下次值得重评的触发条件。风险金额、参照价格和日期随结论一起展示。

## 一轮结束后，怎样决定还要不要辩

资料足以开辩时，多空各发言一次才算完成一轮。每轮结束后，只有同时满足以下三点才建议续辩：

1. 有一个具体、尚未回答的争点。比如空头在最后一句指出，多头引用的是旧订单。
2. 答案可能改变一项结论。比如旧单重发会削弱“新增订单带来短期催化”的理由。
3. 下一轮有可执行的动作。比如核对首次披露日期、重算价格距离，或请多头回应这条新反证。

| 本轮结束时的情形 | 建议动作 | 用户应看到什么 |
| --- | --- | --- |
| 已有可靠证据表明拟入场价、风险线和失效位彼此冲突 | 一轮结束 | 哪个条件冲突，以及改变什么假设才值得重评 |
| 关键反驳刚提出，资料可查或对方尚未回应 | 带着该争点进入下一轮 | 谁反驳了哪句话，用了什么依据 |
| 合同金额尚未披露，现有资料无法推进 | 带着分歧结束 | 缺失的材料，以及将来要等哪项披露 |
| 双方重复原说法，或同一新闻换了证据编号 | 结束并记录无实质进展 | 双方依然认同与分歧的部分 |
| 达到轮数上限或剩余时间要留给裁决 | 停止追加轮次 | 实际完成轮数、停止原因、尚未回应的反驳 |

建议由程序检查引用、算术、轮数和时间预算，由模型识别未决争点及其对结论的影响。每次续辩只带入一个优先问题，同时明确传入原始交易条件。若使用额外的模型判断，也要把这次调用计入预算。

短线评估围绕入场理由、失效条件及已知风险上限判断。完整研报围绕用户关注点、核心判断、置信度和主要风险判断。例如，持仓风险还有可核实的关键反证时，即使短线价格问题已经解释清楚，研报仍有理由续辩。

## 用户怎样看到辩论

每位辩手开始时显示轮次和发言人，生成过程中逐段展示公开发言。每次续辩时说明下一轮要解决的问题，停辩时说明原因。展示内容与最终实录使用同一份发言。生成中断时保留已经展示的内容，标明未完成的发言及实际完成轮数。

| [裁决 Agent](../../backend/agents/judge_agent.py) | 将程序算出的风险比较、停止原因和未决问题带入裁决上下文。现有裁决读取 Markdown 实录，因此新信息也需进入这份文本。 |

| [终端](../../backend/cli.py) | 命令和自然语言两条交互路径都应在研究返回前展示辩论。助手需要保留对应实录供后续追问。 |

当前问答入口给工具调用的时限为 180 秒。设计时要从整次请求里给裁决和输出预留时间，并处理首轮没有完成就超时的情况。此时只报告已取得的事实和未完成状态。

## 候选验收场景

- 固定行情、理由和失效位，只把风险上限从 3% 改为 5%。程序给出不同的风险比较，助手能解释变化，同时保留其他风险。
- 同一组案例覆盖首轮已有答案、可补查后续辩、信息未披露、只增加重复证据、最后发言提出新反证。检查续辩是否对准了真正能影响结论的问题。
- 轮数或时间耗尽时，实录编码实际完成的轮数。裁决和小白摘要都保留尚未解决的问题。
- 分别从终端命令和自然语言发起研报，验证裁决前已经看到双方发言，且显示顺序和内容与最终实录一致。验证研报可因关键反证续辩、也可提前结束。
- 验证无个人风险上限时可先听辩论，随后补上限能沿用本次证据。用普通行情追问、独立演示和旧实录核对证据引用、报告结构和历史记录读取。
