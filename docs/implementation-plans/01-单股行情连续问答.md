# MarketOracle 单股行情连续问答实施方案

## 第一个可交付功能

用户在终端选定一只股票和研究日期，先问走势，再追问判断依据。助手能调用行情工具，在第二轮找回第一轮用到的证据。第一阶段以两轮对话合计只取一次行情为验收目标。

在项目根目录激活 `marketoracle` 环境后，运行 `python -X utf8 -m backend.cli --symbol 300750.SZ --as-of 2026-11-20 --mock-data`。终端显示股票、日期和“模拟行情”。这个开关只替换行情来源，交互演示仍使用已配置的模型。自动验收使用可控的模型替身，可以离线运行。

| 用户输入 | 预期表现 |
| --- | --- |
| “最近走势怎么样？也说一下成交量。” | 调用行情工具，给出数据截至哪一天、价格走势和量能比较，关键数字附本次会话的证据编号。 |
| “刚才说的成交量是跟哪几天比？大约多少倍？” | 指明分母是包含当日在内的最近 20 个交易日均量，给出证据记录的起止日期，复用同一个编号。现有模拟样本的预期值为 1.23 倍，窗口为 2026-10-26 至 2026-11-20。 |

## 实施顺序

1. **建立会话。** 新增 `backend/session.py`，用一个 `ResearchSession` 持有股票、基准日和现有的 `EvidenceStore`。会话内使用同一个问答 Agent 和同一套工具实例，借用框架的消息历史保留“刚才说的”所指的内容。结构化数值以证据库为准。退出终端即结束会话，重新启动即可换股票或日期。
2. **接入问答 Agent。** 新增 `backend/agents/assistant.py`，用已有 HelloAgents 工具调用机制开放行情查询。每轮将会话标的、日期及已有行情证据的编号、交易日、关键指标和降级原因提供给模型。让模型在需要资料时选工具，有充分证据时直接解释。沿用 `backend/tools/hello_adapter.py` 的注册、执行和入库逻辑，以及 `market_data.py` 的指标计算。
3. **约束取数范围与重复调用。** 为问答入口绑定会话标的和日期，在实际取数前核对参数。对同一工具、标的、日期和回溯窗口，已成功取到的结果直接复用原证据编号。用会话内的请求参数关联已有证据，避免复制一份行情数据。失败结果允许后续重试。若需要扩展现有适配器，把这些行为限定在新入口，保留现有调研、辩论入口的参数行为。
4. **接入终端。** 新增 `backend/cli.py`，负责参数、模型配置、模拟行情开关和连续输入。复用 `backend/agents/run_step2_demo.py` 的 `make_mock_tools()` 与项目现有模型配置。输入空行时继续等待，输入 `exit` 或遇到 EOF 时结束。新闻或公告问题在这一版明确提示当前支持行情问答。

## 异常时用户会看到什么

| 情况 | 处理 |
| --- | --- |
| 行情为空或取数失败 | 说明哪只股票、哪个基准日取数失败，保留可重试状态。后续追问不能把失败结果当作行情事实。 |
| 交易日数量不足或指标为空 | 给出实际样本数，说明哪项比较无法完成。尤其注意 20 至 59 根日线也可能缺少完整的 60 日窗口，应读取 `bars_count` 和具体指标。 |
| 模型请求了另一只股票或更晚的日期 | 工具层在取数前拒绝，提示当前会话范围，证据库中只保留本标的、本日期范围的数据。 |
| 行情已入库，但生成回答时模型失败 | 保留已成功取得的证据，提示重试；下一轮可以接着使用。 |

## 如何验收

新增 `backend/tests/test_stock_chat.py`，从与 CLI 共用的问答入口驱动两轮对话。只在模型响应和行情数据源边界使用替身，实际走工具注册、执行和证据入库。用调用计数和证据内容断言行为，允许回答有不同措辞。

- **正常路径。** 第一轮观察到一次行情工具调用。第二轮传给模型的上下文含上轮问题、证据编号和量比依据，可以直接回答，新增工具调用为 0。两轮均引用同一编号，底层取数总次数为 1。模拟样本的 20 日均量为 130000，量比为 1.23，以这两个已入库的字段核对答案。
- **重复请求。** 另设模型第二轮再次请求相同工具参数的用例。此时工具请求共 2 次，底层取数仍为 1 次，证据编号保持一致。分开统计这两个次数，才能看出是助手主动复用了证据，还是重复请求被缓存接住了。
- **隔离与恢复。** 换一个新会话后看不到上次材料；越界参数不会触发取数；先失败再成功可重新取数并产生有效证据。用短样本确认回答能标明缺失的比较区间。
- **验证命令。** 在项目根目录用项目环境运行下列命令。第一条针对新增行为，第二条用于收尾回归，包含已有工具测试。再用上文两句示例做一次真实模型、模拟行情的交互验收，观察模型能否自行选工具和复用证据。

```powershell
& D:/miniforge3/envs/marketoracle/python.exe -X utf8 -B -m unittest discover -s backend/tests -p test_stock_chat.py -v
& D:/miniforge3/envs/marketoracle/python.exe -X utf8 -B -m unittest discover -s backend/tests -v
```

## 后续功能顺序

第一阶段通过后，第二阶段给同一问答入口开放新闻和风险工具，验收“刚才说的是行情，那最近有没有回购消息”这一类跨工具追问。第三阶段让 `run_stock_deep_research` 接收当前会话的证据和配套工具实例，沿用编号继续补证，把研报交回会话供追问。前端和跨会话长期记忆留待这条研究路径跑通后单独规划。
