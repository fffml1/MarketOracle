# 财报与公告 PDF 解析试验及入库计划（个人开发版）

## 1. 目标与输入

一个人可以运行整批任务。样页选择、规则检查、失败隔离和验收均由程序执行。优先保障财务数字能追溯到对应报告、页码、表头和单位。资料覆盖与解析质量分开记录。

输入为 `backend/data/公告索引.csv` 和对应的 179 份 PDF，共 5,463 页。股票代码保留前导零，公告 ID 区分披露版本，SHA-256 标识文件内容。解析器首选 pdfplumber。向量使用 `qwen3.7-text-embedding-flash`，应用数据库只用 Chroma。样本清单、解析缓存和错误记录用本地 JSONL 保存，建议置于 `backend/data/rag/`。

| 来源 | 页数 | 自动选择方式 |
|---|---:|---|
| 五粮液三季报更新前后、茅台和宁德时代三季报 | 8 | 公告 1224774300、1225273123、1224764517、1224721971 各取前两页 |
| 三家公司 2025 年报 | 6 | 公告 1225114741、1225273091、1225002214 各取首组符合条件的相邻页。条件为表头含金额期间，下一页出现多行相同列布局；没有命中则取数字行最多的一对相邻页并记录回退原因 |
| 五粮液更正公告与分红实施公告 | 4 | 公告 1225273122、1225417855 各取前两页，检查修订版本及每股与每十股的区别 |

这些样页用于发现程序退化及比较资源开销。样页上的通过率不能代表全库财务准确率。

## 3. 解析、校验和自动降级

1. **定位原文。** pdfplumber 提取带坐标的文字、表格边界和单元格。正文按段落切分，保留含税、每十股、单位等限定语；表格区域与正文分开，防止同一错误表格又作为普通正文进入检索。
2. **验证表格行。** 指标、金额、期间、列标题和单位分别保留原文位置。根据横向坐标将数值匹配到唯一表头，单位可以来自指标名、表头或整张表的单位说明。负号、括号、百分号、零、空白及破折号保留原貌。只有表头、数值页、单位及适用口径能明确对应的行才生成数值证据。
3. **验证续表。** 上下页的列位置、单位和口径应兼容，出现新标题或可匹配多个表头时停止继承。每条跨页证据同时记录表头页与数值页。
4. **让备用工具只处理难页。** 错列或合并表头有歧义时，对同页或相邻页组尝试 Docling；文字层为空或乱码且页面含内容时尝试中文 OCR。备用结果重新过同一套规则。两路解析存在实质分歧时保留原文和原因，跳过相应数值。首版可只开 pdfplumber，统计跳过原因后再决定是否部署备用模型。
5. **隔离到块。** 同页合格正文可以发布，无法可靠绑定的表格自动跳过。记下公告 ID、页码、块位置、规则编号和解析器版本，整批继续。将来规则改善时只重跑受影响的块。若提问所需数据均被跳过，返回证据不足及可定位的原文链接。

### 3.1 片段切分策略

| 内容 | 切分单位 | 上下文 |
|---|---|---|
| 财报正文和经营分析 | 在同一小节内按完整段落合并，目标 300～600 个中文字符。超过约 800 字时优先在段落或完整句子边界拆分 | 每块带公司、报告期和小节标题。只有长段必须拆开时才允许重复上块末句；标题切换后停止重叠 |
| 财务表格 | 一个指标行一个片段，同行的单季、累计、同比和原因列一起保留 | 每个数值配完整列标题和单位，附表名、报告期和适用口径。续表按上一节校验并保留表头页和数值页 |
| 分红、回购等专项公告 | 每项完整条款一块，单一事项的短公告可以整体保留 | 条款带对应方案状态、日期和限定语，如每十股、含税。可独立理解的短条款无需补足目标长度 |
| 更正公告 | 同一指标的更正前值、更正后值及可明确关联的原因放在同一块 | 保留新旧标签与受影响报告期。原报告和更新版各用自己的公告 ID，分别切分 |

传给 Qwen 的文本与 Chroma 的 document 使用同一份内容。metadata 保存股票代码、报告期、公告 ID、版本、披露日、起止页和来源链接。正文跨页续句可合并并保留页码范围。依据同一公告中的页码和表格区域坐标排除重复正文，保留相邻表外脚注。

切分验收使用合成样例自动检查：每条数值均有对应表头、单位和来源页；同一行的单季值与累计值可从同一片段读取；跨页片段可定位两页；相邻章节与不同版本互不串入；表格区域仅生成一次证据。分红样例同时断言“每十股”和“含税”随金额保留。

## 4. 自动验收

| 检查 | 实施方式 | 验收依据 |
|---|---|---|
| 来源与完整性 | 逐份核对文件哈希、页数、页码范围。每页记录已全部解析、部分解析、全部跳过、无正文或运行失败 | 所有输入页都有状态；入库片段均能回溯至本地原页；运行失败可按公告重试 |
| 防错规则 | 用程序生成的小表格构造已知输入：单季与累计、元与千元、同比百分号、负数、破折号、合并表头及跨页。额外构造缺单位、表头冲突等反例 | 正例输出预设的值与口径；反例触发跳过。用交换两列、删除单位等变换验证这些检查真的能报错 |
| 版本与引用 | 固定同一公司、报告期与类型。以 2025-11-01 和 2026-05-01 两个截止日检索五粮液 2025 三季报 | 分别选中公告 1224774300 和 1225273123，数值片段可追溯到所选版本。已有新版但数值无法解析时明确报告缺口 |
| 实际文档表现 | 按公司与模板统计包含表格的页数、通过和跳过的候选行数、无候选行的疑似财务页、备用工具触发数、耗时及失败原因 | 展示分子和分母。解析器一致性只作诊断信号；识别到的候选行通过率也无法衡量未检测到的表格 |
| 入库一致性 | 对固定样本重复执行，并模拟在写入中途停止后恢复 | 活跃集合的片段 ID 与通过检查的清单一致；无重复、无旧版片段混入 |

程序生成的小表格检验工具行为。真实文档仍可能出现两个解析器同时选错表头、整表漏检等错误。运行报告只公布覆盖范围、规则通过率和已知缺口；真实准确率保持未知。报告还应单列各公司各报告期的营收、净利润等关键指标是否可检索，防止“所有页都处理过”掩盖业务缺失。

## 5. 实施顺序

1. **本地验证。** 生成样页清单，用 pdfplumber 完成提取、规则检查、合成用例和跳过原因汇总。此阶段无需 embedding API。以难页数量和缺失指标决定是否值得加 Docling 或 OCR。
2. **五粮液试运行。** 跑 52 份公告。将合格正文及表格行向量化，记录模型 ID 和维度。Chroma 元数据包括股票代码、公告 ID、报告期、披露日、版本、块类型、起止页、哈希和来源；披露日保留整数形式以便范围过滤。按原文哈希、解析版本和位置生成稳定片段 ID，支持断点续跑。
3. **扩至三家公司。** 前述来源、规则、版本与入库检查通过后处理 179 份。逐页清点并自动汇总各公司缺失项。修订解析器时以新集合完成核对后再切换；Qwen 输入按内容和模型配置缓存。向现有 EvidenceItem 的 payload 返回原文、页码和链接，published_at 保留披露日。

## 6. 第 1 阶段运行与复核

在仓库根目录使用 Python 3.11 或更新版本，环境需包含 pdfplumber（本轮使用 0.11.9）。本机可直接使用已有的 `paperreader` 环境。

```powershell
python -X utf8 -B -m unittest backend.tests.test_rag_validation -v
python -X utf8 -B -m backend.rag.validate
```

运行产物位于 `backend/data/rag/`。首次运行会生成 `sample_manifest.jsonl`，后续运行读取同一清单并核对原文哈希。年报优先选取至少有两行能按同一表头和列布局验证的相邻页。难例筛选使用 PDF 文字层和图像对象，少文字的阈值为 100 个非空白字符。

| 文件 | 用途 |
|---|---|
| `sample_manifest.jsonl` | 20 张固定样页及选取理由 |
| `inventory.jsonl` | 全量文件核对和物理页清点 |
| `sample_pages.jsonl` | 样本页解析状态、候选行数和耗时 |
| `fragments.jsonl` | 通过规则的正文、表格及更正片段，含原文位置 |
| `skips.jsonl` | 跳过规则、公告、页码、块位置及解析器版本 |
| `report.json` | 来源验收、按公司和模板汇总、关键指标与截止日版本核对 |

可通过 `--index` 指定公告索引、通过 `--output` 指定独立的实验输出目录。第 1 阶段的解析质量统计以 20 张样页为分母，全量清点用于确认输入完整性。暂以 pdfplumber 处理规则可明确绑定的行，依据跳过记录和缺失指标评估是否引入 Docling 或中文 OCR。

## 7. 第 2 阶段五粮液试运行

在仓库根目录使用项目的 `marketoracle` Conda 环境。输出位于 `backend/data/rag/wuliangye/`，其中 `report.json` 按报告期和披露版本列出已找到的指标页码，`skips.jsonl` 保留无法确认的块和原因。

```powershell
conda activate marketoracle
python -X utf8 -B -m backend.rag.pilot
python -X utf8 -B -m backend.rag.lookup --period 2025年三季度 --as-of 2025-11-01
python -X utf8 -B -m backend.rag.lookup --period 2025年三季度 --as-of 2026-05-01
```

查询命令默认取当期营业收入。可以用 `--metric` 查询归母净利润或经营现金流量净额，或用 `--scope 累计` 查询年初至报告期末累计值。返回值附公告链接、原表头和物理页码。所选披露版本缺少证据时，查询显示该版本的缺口。

本轮用 Conda 环境内的 pip 安装了 pdfplumber 0.11.9 和 Chroma 1.5.9。为兼容项目中的 hello-agents 1.0.1，使用 Pydantic 2.13.5 和 Kubernetes Python 客户端 35.0.0。

向量入库还需配置 `DASHSCOPE_API_KEY` 和 `MARKETORACLE_EMBEDDING_URL`。可在项目根目录的 `.env` 或进程环境中配置。地址可填写所属地域的 OpenAI 兼容 HTTPS 基础地址（以 `/compatible-mode/v1` 结尾），也可填写 DashScope 文本向量完整 HTTPS 地址。入库使用 `qwen3.7-text-embedding-flash` 和 1,024 维向量。首次写一批后退出，再运行两次，分别核对续跑和重复运行。断点后的下一次运行只补齐缺少的片段。全部片段和截止日版本核对通过后，生成 `chroma_ready.json`。

```powershell
python -X utf8 -B -m backend.rag.ingest --max-batches 1
python -X utf8 -B -m backend.rag.ingest
python -X utf8 -B -m backend.rag.ingest
```
