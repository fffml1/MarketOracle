# 实时多空辩论与短线评估实施方案

## 首版交付

用户在同一只股票、同一研究基准日的终端会话里，可以直接问“我准备做短线，现在能上车吗”，也可以用自然语言或 `/研报 [关注点]` 发起完整研究。进入辩论后，终端显示轮次、发言人，并在该辩手说完之前逐段显示公开正文。每轮结束时说明接下来核实什么，或为什么可以结束。双方各完成一次发言计一轮，两个研究入口均试行最多三轮。

例如，用户提出“假设 100 元入场”，多头提出有证据支持的 96 元失效位，空头认可其依据。摘要可先说明两者相距 4%，个人风险上限待补。用户再说“跌 3% 就走”，助手沿用刚才的依据算出 97 元，说明会先触及个人风险线。若空头质疑 96 元的依据，摘要同时保留这条分歧。

本方案按终端首发编排。网页接入可复用同一套发言事件，另需后端传输接口及 React 辩论视图。独立研报脚本也使用动态轮数，独立教学演示保留可复现的固定两轮。

## 实施顺序

### 1. 先让一段真实发言穿过终端

从现有两轮流程入手。本机 HelloAgents 提供流式模型接口，现有辩手调用的是返回整段文本的 `ReActAgent.run()`。先用一次带补证工具调用的发言查明实际事件边界。只把可识别的公开最终答复片段交给显示层；工具参数、推理过程、重复的完成通知都留在显示层之外。若框架只在完成时交出最终答案，将补证和公开陈述分为两步，用已取得的证据单独流式生成一次公开正文，并把增加的调用计入预算。

本机 ReAct 的流式事件可包含工具循环中间文本，最终回答也可能来自 `Finish.answer` 工具参数。验证必须覆盖这两种路径。步骤上限或输出截断时检查运行终态，即使已有文字也只计作未完成发言。

验收时用可暂停的模型替身发出第一段，暂停第二段。此刻终端应已有第一段，实录状态为发言中。恢复后逐段拼接出的全文必须等于最后可追问的原话。真实模型配模拟行情再走一次，确认首段确实在发言结束前到达。完成后的引用核查结果另行标注，保留用户看到的原话。

### 2. 加入动态停辩与时间控制

第一轮双方都发言后，检查三个问题：尚未回答的反驳是什么，答复可能改变哪项判断，手上还有什么具体核实动作。三项齐全才追加一轮，每次只追一个最重要的争点，并重新传入原始交易条件或研报关注点。短线关注入场逻辑与失效条件；研报还要考虑核心判断、置信度和主要风险。

首版优先从现有发言提取判断依据。程序检查引用、算术、轮数和期限；模型提出争点及其影响。重复转载按来源、披露日期和事实内容识别。关键信息尚未披露时，记录等待的材料。到上限仍出现新反证时，将最后一方的反驳原样关联到未决问题。

问答助手配置的 180 秒是工具超时；直接执行 `/研报` 和独立脚本另经研究编排启动。各入口都应向编排层提供截止时间，辩手和工具调用继承剩余预算。依据样例实测为裁决、反思和可能的修订预留时间。首轮未完成就到期时展示已取得的事实和未完成状态；完成过一轮时仅依据已完成的交锋作有条件归纳，单列中断的发言。裁决失败则保留实录并标记研报未生成，上一份成功报告仍可按其身份查阅。

### 3. 接通完整研报和追问

把动态策略接入 `conduct_research()`，覆盖终端命令、助手研究工具和独立脚本。保留现有报告返回形式及落盘 JSON 的 `report`、`debate`、`evidences` 三部分。实录新增字段提供兼容默认值；旧记录缺停止原因时显示“未记录”，读取时按成对的已完成发言核对轮数。

助手当前在 `research()` 中丢弃了返回的实录。改为保存对应报告与实录；“刚才空头怎么反驳”定位到具体轮次和原话。同步研究工具可能在线程中继续执行，即使外层已超时。为每次研究分配运行标识，结束后关闭该次输出和结果提交入口，隔离仍在执行的工具写入。用“旧调用超时、下一请求开始、旧结果才到达”的顺序验证终端、会话证据与最近报告均属于正确的运行。

### 4. 接入短线评估与风险追问

通过现有问答工具机制承接“能不能追”“准备短线”等意图。普通行情问题走已有直接回答路径。优先使用明确的用户拟入场价并标为“用户假设”；缺价时可采用基准日及之前最近有效收盘价，并展示实际交易日和来源。两种价格均缺失时仍可讨论有依据的定性条件，标明距离暂无法计算。

风险上限可以稍后补充。确认是相对入场价的可承受跌幅后，程序计算风险线为入场价 ×（1 − 跌幅）。账户损失或仓位风险需要先问清口径。有依据的失效位才参与价格比较，来源相互矛盾时列出条件判断。价格须为有效正数，百分比越界时请用户更正。仅补风险上限且其余条件相同时，使用本次证据重算；新公告或入场前提变化时先指出受影响的理由，再决定是否需要补证或续辩。

## 验收与回归

在项目根目录运行。新增聚焦该功能的 `backend/tests/test_live_debate.py`，用可控的模型、行情源和时钟替身驱动实际编排与终端输出。

| 验收案例 | 通过标准 |
| --- | --- |
| 终端命令及自然语言发起研报 | 两条路径均在多头发言完成前看到正文；每段只出现一次。实录、界面和追问中的引文一致。 |
| 一轮即可结束；旧订单可查；合同金额未披露；同一新闻换编号 | 依次得到首轮停止、围绕首次披露日期续辩、记录缺口后停止、识别重复后停止。 |
| 第三轮末出现新反证；首轮中断；裁决超时 | 依次保留未回应反驳、显示零个完整轮次并保留部分原文、保留实录并明确报告状态。 |
| 100 元入场、96 元失效，依次补 3% 和 5% | 风险线分别为 97 和 95 元，价格约束比较随之改变，新增取数和辩论次数均为零；其他争议仍出现在摘要。 |
| 旧实录、完整研报与短线评估交替、普通行情追问、固定演示 | 旧 JSON 可读；两种研究各自找回对应证据和原话；普通问答可直接返回；固定演示完成两轮。 |
