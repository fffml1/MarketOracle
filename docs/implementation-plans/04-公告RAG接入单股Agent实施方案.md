# 04｜把财报与公告 RAG 接入单股 Agent

状态：三阶段代码已实现。依赖方案 03 的五粮液试点产物；未重跑 PDF 解析或入库。各路径开关见[后端组件与协作说明](../后端组件与协作说明.md#五粮液财报与公告试点)。

## 1. 用户能得到什么

| 用户在当前会话提问 | Agent 应怎么做 | 回答的最低要求 |
| --- | --- | --- |
| 五粮液 2025 年第三季度单季营收多少？ | 查报告表格，取本报告期列 | 金额、单位、报告版本、PDF 物理页码、来源链接和证据编号 |
| 那前三季度累计呢？ | 沿用标的、指标和报告期，改查累计列 | 不复用上次的单季数；没有通过校验的累计列就说明缺口 |
| 公司在前期会计差错更正公告里怎么解释原因？ | 在基准日可见的公告正文中检索 | 引出支持答案的原句并给页码；不把研究员的猜测当作公司表述 |
| 在宁德时代会话中问同一问题 | 先查知识库覆盖范围 | 明示本地库尚未覆盖；不能误查五粮液，也不能说宁德时代没有披露 |

本期只接五粮液，复用 Web、CLI、研究会话与证据存储。不重跑 PDF 解析，不重新向量化，不改前端协议，不扩充公司或财务指标。精确取数只承诺现有三项：营业收入、归母净利润、经营现金流量净额，且以原表能验证为准。

## 2. 现有能力与接入位置

| 仓库相对路径 | 已有能力与需要改动的地方 |
| --- | --- |
| `backend/rag/lookup.py`、`backend/rag/source.py` | 已有按截止日选版本、按指标与口径选列的逻辑；`lookup` 使用固定的 `STOCK`，不能接收任意股票后直接调用 |
| `backend/rag/ingest.py`、`backend/data/rag/wuliangye/` | 已有片段校验、向量化和持久库；就绪清单记录了 9,663 个片段、模型、维度和集合名。查询端读取，不调用入库流程 |
| `backend/tools/hello_adapter.py`、`backend/schemas/evidence.py` | 已有角色注册表、`EvidenceStore`、`EvidenceBundle`；既有工具的成功缓存只按 `lookback` 区分，不适用于不同报告期、指标或检索句 |
| `backend/agents/assistant.py` | 聊天有独立注册表，当前提示会引导部分公告问题走深研；需同时改工具注册、路由提示和追问上下文 |
| `backend/agents/research_team.py`、`backend/agents/run_full_pipeline.py` | 深研另有角色注册和独立启动入口；只改聊天入口不会自动覆盖独立深研 |

主链路：问题 → Agent 选择工具 → 后端绑定股票、基准日 → 检索并核验 → 写入本次会话的证据库 → Agent 引用回答。模型不决定资料的可见日期，也不负责从相似文本里猜一个财报数字。

## 3. 第一阶段：聊天可以精确查数（可独立交付）

1. **加载只读资料。** 在 `backend/rag/` 增加查询服务，维护明确映射 `000858.SZ → 000858 → wuliangye`。首次访问时用 `read_index`、`load_audited_blocks` 加载并校验，只共享完整的只读数据快照；会话证据不共享。精确取数不要求 Chroma 或 embedding 密钥。保留现有 `lookup` CLI 的默认行为。
2. **公开工具契约。** `get_financial_metric(period, metric, scope)`，报告期形如 `2025年三季度`，指标限定于现有 `METRICS`，口径限定为“本期／累计”。股票和基准日从会话传入，不让模型覆盖。仅说“三季报营收”而上下文不能判断口径时，询问“单季还是前三季度累计？”。历史回看首版用不同基准日的独立会话，避免以后披露的资料污染早期答案。
3. **组装证据。** 唯一数值才建 `FUNDAMENTAL` 证据；同一值出现在多页时只记录一条事实，保留各页片段 ID。`published_at` 取披露日。`payload` 保留公告 ID、版本、报告期、指标、原表头、数值、单位、页码、片段 ID 和来源链接。`to_prompt_text()` 不展示完整 payload，因此页码、链接和关键数字也必须进入模型可见文本。沿用现有证据编号机制，片段 ID 留作原文定位。
4. **注册和路由。** 在 `StockChatAssistant` 注册独立工具适配器，复用 `EvidenceStore` 与既有工具响应，不沿用行情缓存。直接问数字不启动完整研报。重复查询仅在股票、基准日、报告期、指标、口径与数据版本均相同时复用；错误不缓存。追问“哪一页”直接引用已记录证据。
5. **明确不能回答的情况。** 区分“截止日无报告”“所选版本缺少经校验的值”“同一口径有多个不同值”。分别解释原因，不写入确定数字，不回退旧版，不转向语义检索猜值。阶段出口：通过下文 A–D。

## 4. 第二阶段：聊天可以查公告原文

1. **工具契约。** `search_announcements(query, period?, category?)`，股票与截止日仍由会话绑定。首版建议最多返回 3 条，每条不超过 500 字，带标题、披露日、公告 ID、片段 ID、页码范围及链接。同一片段去重；同时问数字和原因则分别调用两种工具、分别引用。
2. **打开就绪集合。** 从 `chroma_ready.json` 读取集合名，核对完成标志、片段摘要、集合计数、模型及维度。不创建空集合，不触发自动建库。用与入库相同的 `qwen3.7-text-embedding-flash`、1,024 维生成查询向量；复用已有端点校验和凭据配置。只向服务发送必要查询短句，不发送持仓信息或对话全文。
3. **先限定可见资料，再算相似度。** 根据索引取绑定股票、披露日期不晚于基准日且类别匹配的公告。定期报告按报告期用 `select_version` 保留当时可见的有效版本；其他独立公告按 ID 保留，不能把同类别多份更正或分红公告压成一份。将允许的 ID、股票代码、整数披露截止日和正文类型传入 Chroma 检索。候选集为空直接结束。命中后再按片段 ID 和源哈希核对；不做“全库取前三，再过滤”的查询。
4. **回答有依据才引用。** 返回原文而不是另一份生成式摘要，明确原文是证据、不是指令。片段只提“发生更正”而未说明原因时，答“检索到更正，但当前片段不足以说明原因”。不把“没找到”写成“未发生”。通过人工标注问题核对命中质量，不凭经验硬设通用相似度阈值。
5. **隔离故障。** 缺密钥、向量超时、维度不符、索引不完整与合法的零命中分别处理。限制检索次数和超时，不把错误写成无结果，不暴露凭据。仅本工具不可用，财报查数与行情仍可用。阶段出口：通过 E、F。

## 5. 第三阶段：研究员和裁判用同一套证据

- `quant` 增加精确指标工具；`catalyst` 和 `risk` 增加公告正文工具。保持原有行情、新闻和风险工具。辩手优先引用已录入事实，裁判使用已有合法证据编号集合，不另查向量库。
- 在聊天内深研与独立 `run_stock_deep_research` 两个构造入口核对注册。模拟模式注入固定结果、标注模拟，不读真实文件或访问外部向量服务；真实模式按就绪状态启用。研究取消后不得写入迟到的检索结果，沿用现有运行锁和取消检查。
- `ask()` 会序列化已有会话证据。RAG 接入时只把简短事实、必要原文和引用定位交给模型，不把全文、向量和全部坐标逐轮回灌。相同事实复用证据编号；缩短提示不删除历史报告引用的记录。阶段出口：通过 G 并复测 A、F。

## 6. 验收清单

| 编号 | 用例 | 通过标准 |
| --- | --- | --- |
| A 历史版本金标 | 两个独立五粮液会话，同问 2025 年第三季度单季营收 | 截至 `2025-11-01` 返回 `8,174,336,700.05 元`、公告 `1224774300`；截至 `2026-05-01` 返回 `7,127,755,606.32 元`、公告 `1225273123`。各自来源、页码、编号可核验 |
| B 追问 | 单季改问累计，再测一条口径含糊的问题 | 不复用单季列；缺值不猜；无法确定口径时澄清 |
| C 边界 | 未覆盖股票、报告披露前、缺值新版、同口径冲突值 | 四类结果可区分；不拿旧值或别家数据兜底；不写入虚假事实 |
| D 真实聊天链路 | 在 Web 和 CLI 各问一次 A，然后问“原文第几页？” | 不启动深研；引用可解析；关闭 embedding 后仍能回答，数字与本地查询一致 |
| E 正文质量 | 人工从试点公告选 5 个能回答的问题，事先记录公告 ID、物理页和原句；另选 3 个无依据问题 | 建议试点门槛：真实检索的前 3 条均按题核验，5 个正例各有至少 1 条支持答案，3 个反例均不编造；任何未来或失效版本命中均不通过 |
| F 故障隔离 | 注入超时、集合缺失、摘要不符、运行中取消；并行两会话查不同日期 | 错误与零命中不同，未受影响路径仍可用；取消后不写证据，没有跨会话、跨日期污染 |
| G 深研 | 模拟模式离线回归，真实模式一次人工联调 | 最终报告引用可在本次证据库解析并回到原公告；模拟测试零外部请求；缺口不冒充事实 |

实施时新增工具契约、路由、日期隔离和故障用例。开发中只跑对应快测，阶段集成后再跑 `python -X utf8 -B -m unittest discover -s backend/tests -v`。常规测试用小样本和替身；真实 embedding 质量标注单独执行，不作为默认离线测试。A 的两个数字已在查询层核实，不能算作 Agent 已通过验收。

## 7. 启用、观察与回退

依次启用聊天查数、聊天查原文、深研复用。建议三者可单独关闭，关闭时同步移除工具注册及对应提示。记录工具名、标的、基准日、数据版本、命中数、耗时及失败类型，不记录密钥和完整提问。语义质量未达标只下线语义路径；发现串标的或错版立即关闭受影响路径，用 A、F 验证修复。回退无需删除现有库、修改 PDF 或重写历史报告。
